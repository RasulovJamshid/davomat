# Учет сотрудников, времени и задач

## Доступ

Роли ADMIN и MANAGER дают рабочее место руководителя. EMPLOYEE открывает личный кабинет. Сервер проверяет действительность аккаунта, компанию и роль на каждом запросе.

В разделе «Сотрудники» руководитель создает профиль, задает оплату и предоставляет доступ к аккаунту. «Удалить сотрудника» переводит профиль в архив, отключает вход и отменяет будущие смены без отметок. История посещений, задач и расчетных листов сохраняется. Самоудаление запрещено; менеджер не может удалить профиль руководителя.

## Посещаемость и график

В личном кабинете доступны «Начать рабочий день», «Закончить рабочий день» и отметки перерыва. Время задает сервер. Повторные и недопустимые события отклоняются; блокировка профиля в транзакции защищает от одновременных нажатий. Начатую в предыдущий день смену можно завершить после полуночи. Повторное начало после завершения рабочего дня разрешается на следующий день.

Отметки браузера имеют источник WEB и не содержат подтверждения по селфи/GPS. Мобильный маршрут сохраняет свою проверку устройства, селфи и координат.

В «Рабочем графике» задаются смены и перерывы. Шаблоны и повторяющиеся расписания доступны в существующих инструментах планирования. Дни без смен считаются выходными. Расчет нормы использует только опубликованные смены.

История отметок, отчет за день/неделю/месяц и задачи доступны в карточке сотрудника на вкладке посещаемости. Сотрудник видит собственный отчет в «Мои рабочие часы».

## Задачи

«Задачи» доступны в меню руководителя и личном кабинете. Руководитель указывает название, описание, исполнителя, срок и приоритет. Срок вводится в местном времени браузера и хранится как абсолютное время.

Сотрудник переводит только свою задачу: Новая → В работе → Выполнена. Руководитель может изменить статус, включая возврат на доработку. Изменения статуса записываются в аудит. Отчет считает выполненные задачи по дате завершения в часовом поясе компании.

## Оплата и отчеты

В профиле и форме добавления сотрудника есть тип оплаты: фиксированная или почасовая.

- Почасовая основная оплата: фактические часы × часовая ставка. 168 × 30 000 = 5 040 000 сум.
- Фиксированная основная оплата: месячный оклад × min(фактические часы периода, плановые часы периода) / плановые часы полного месяца. Например, 5 280 000 × 168 / 176 = 5 040 000 сум.
- Если период охватывает несколько месяцев, расчет выполняется по каждому месяцу и суммируется. При отсутствии месячного графика фиксированная часть равна нулю. Перед расчетом необходимо опубликовать полный месячный график.
- Часы — закрытые интервалы работы за вычетом отмеченных перерывов. Незавершенный интервал не включается в оплату. Смена через полночь относится к дате начала смены, а работа без смены — к дате начала рабочего дня.
- Пропуск — опубликованный рабочий день, уже закончившийся без отметки прихода. Опоздание учитывает допуск, заданный в смене.
- Сводный отчет показывает предварительную основную оплату без налогов, надбавок и удержаний. В разделе зарплаты расчетные листы дополнительно применяют настроенные правила надбавок и удержаний. Для почасовой оплаты обычная стоимость сверхурочных часов уже включена в основную часть; отдельно добавляется только повышающая часть коэффициента.
- Утвержденные и оплаченные расчетные листы автоматически не перезаписываются.

«Отчеты» позволяют выбрать период до одного года и скачать CSV с UTF-8 BOM для Excel. «Печать / PDF» открывает печать браузера: выберите «Сохранить как PDF». Это CSV и печатный PDF, отдельного экспорта XLSX нет.

На главном экране руководителя добавлены общее количество сотрудников, активные и выполненные задачи, фактические часы и предварительная основная зарплата текущего месяца.

## Обновление и проверка

Добавлены миграции `017_tasks_and_workforce_summary.sql` и `018_actual_hours_payroll.sql`. Примените их штатным `npm --prefix server run migrate` или запуском сервера с `RUN_MIGRATIONS=true`. Миграции обновляют схему и формулу; существующие выплаты не пересчитывают.

Проверки:

```text
npm run build:all
npm run test:all
npm --prefix server run test:workforce
npm run test:e2e -- e2e/tasks-reports.spec.ts
```

`test:workforce` требует собранный API и отдельную PostgreSQL-базу с примененными миграциями, заданные `DATABASE_URL` и `JWT_SECRET`. Он создает две тестовые компании, проверяет расчеты 168/176 часов, доступ между компаниями и сотрудниками, статусы задач, повторные и ночные отметки, изменение типа оплаты и архивирование, затем удаляет свои данные. Браузерный тест использует стандартные демонстрационные аккаунты и проверяет сценарий задач, личный отчет и выгрузку на desktop/mobile.
